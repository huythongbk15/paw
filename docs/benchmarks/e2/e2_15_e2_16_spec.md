# E2-15: Per-role token/cost ceilings and hard-stop behavior

## Contract

`ExecutionProfile` gains `role_token_ceil` (per-role max context tokens) and
`role_cost_ceil` (per-role max USD cost). `ModelRouter.route()` and
`route_with_explain()` check the selected model against the active role's
ceiling and stop visibly when exceeded.

### API

```python
profile = ExecutionProfile(
    role_token_ceil={"reasoning": 16000, "fast": 4000},
    role_cost_ceil={"reasoning": 0.10, "fast": 0.01},
)
```

### Behavior

- Ceilings are per-role (e.g., "reasoning", "fast", "coding").
- If the selected model's `max_context_tokens` exceeds `role_token_ceil[role]`,
  return `ModelSelection(model_name="", reason=...)`.
- If the model's estimated cost exceeds `role_cost_ceil[role]`, return the
  same visible stop.
- `getattr` is used for attribute access to support fake profile objects in
  tests.
- No ceiling defined (empty dict / None) → no check (backward compatible).

# E2-16: Record observed usage once without double accounting

## Contract

The runtime logs two distinct ledger events:

1. `STEP_PROPOSED` — logs `estimated_cost` (pre-execution estimate, for
   the policy/autonomy gate).
2. `STEP_EXECUTED` — logs `resources_used` (actual observed usage from
   `ExecutionObservation`).

### Double-accounting rule

Summing `estimated_cost` (from STEP_PROPOSED) + `resources_used` (from
STEP_EXECUTED) would double-count. The **authoritative source for actuals**
is `STEP_EXECUTED.resources_used`. The `estimated_cost` is only a pre-gate
budget check — it is NOT added to actual usage totals.

### Implementation

In `PawRuntime._run_step()`, after updating `self.autonomy.usage` from
`observation.resources_used`, the runtime calls `log_step_executed()` with
`resources_used=observation.resources_used.model_dump()`. This ensures:

- The actual usage is persisted to the ledger (survives crashes).
- The autonomy usage tracking (in-memory) uses the same single source.
- No code path sums `estimated_cost` into actual usage.
