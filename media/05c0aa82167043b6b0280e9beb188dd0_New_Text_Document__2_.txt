# PAW Personal Agent OS — Master Implementation Prompt

Bạn là Principal Software Architect + Staff AI Agent Engineer chịu trách nhiệm xây dựng **PAW — Personal Agent Workstation**, một personal AI agent chạy CLI-first, local-first, nhẹ tài nguyên, model-agnostic và có kiến trúc plugin/provider.

## 1. Mục tiêu sản phẩm

PAW không phải là một wrapper quanh một agent framework có sẵn.

PAW phải là một **Personal Agent Core độc lập**, có thể sử dụng các dự án bên ngoài như provider/executor nhưng không phụ thuộc chặt vào bất kỳ provider nào.

Triết lý:

1. CLI first, GUI optional.
2. Local first, cloud only when useful.
3. Cheap model first, expensive model only when justified.
4. One personal identity, many replaceable workers.
5. Task Graph first, agent swarm second.
6. Context must be selected, never blindly dumped.
7. Skills are first-class capabilities.
8. Memory records knowledge; Task Ledger records actions.
9. Every external integration must be replaceable.
10. Zero-daemon mode must be the default.

# 5. TaskResult contract

Tất cả executor phải normalize về cùng một structure.

Ví dụ:

```python
class TaskResult(BaseModel):
    task_id: str
    status: Literal[
        "completed",
        "failed",
        "partial",
        "blocked"
    ]

    summary: str

    artifacts: list[Artifact] = []
    decisions: list[Decision] = []
    evidence: list[Evidence] = []

    files_changed: list[str] = []

    executor: str | None = None
    model: str | None = None

    usage: Usage | None = None

    error: ErrorInfo | None = None
```

Không để output format của provider leak vào PAW Core.

# 21. Required workflow for every phase

Before coding:

1. Inspect current repository.
2. Summarize existing architecture.
3. Identify exact scope of CURRENT_PHASE.
4. Identify files expected to change.
5. Define acceptance tests.

Then implement.

After implementation:

1. Run unit tests.
2. Run integration tests.
3. Run lint.
4. Run type checks if configured.
5. Run phase acceptance scenarios.
6. Inspect git diff.
7. Check for architecture leakage.
8. Check backward compatibility.

Return:

```text
PHASE:
STATUS: PASS | PARTIAL | FAIL

IMPLEMENTED:
...

TESTS:
...

ACCEPTANCE CRITERIA:
[PASS] ...
[PASS] ...
[FAIL] ...

...

...

...
```

# 25. Definition of success

PAW is successful when the user can run:

```bash
paw
```

and obtain one coherent personal agent that:

- remembers relevant personal information,
- discovers and loads relevant skills,
- selects appropriate context,
- selects appropriate model,
- selects appropriate executor,
- researches with evidence,
- executes coding/tool tasks,
- respects permissions,
- records what happened,
- learns useful long-term knowledge,
- avoids unnecessary expensive models,
- runs primarily from the terminal,
- and remains independent of any single AI vendor or agent framework.

Build PAW as a product.

Do not build an integration demo.
