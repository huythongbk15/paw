# PAW — Personal Agent Workstation

## MASTER IMPLEMENTATION PROMPT

You are the Principal Software Architect and Staff AI Agent Engineer responsible for designing and implementing a new open architecture named:

# PAW — Personal Agent Workstation

PAW is a **greenfield project**.

It is NOT an integration project.

It is NOT a wrapper around existing agent frameworks.

It is NOT a fork of another agent project.

It must be designed as an independent Personal Agent architecture whose important concepts, state, policies and data models are owned by PAW itself.

---

# 0. CRITICAL ARCHITECTURAL CONSTRAINT

The following projects MUST NOT be used as runtime dependencies, base code, SDK dependencies, embedded services, orchestration layers, or architectural foundations:

- QwenPaw
- DeepSeek Harness
- NotebookLM
- Google Antigravity

This requirement is absolute.

DO NOT:

- clone their repositories;
- fork their code;
- copy internal implementation code;
- import their Python/JavaScript packages;
- launch them as subprocess workers;
- wrap their CLIs;
- call their internal APIs;
- depend on their runtime;
- design PAW interfaces around their APIs;
- create adapters whose purpose is to run these four systems;
- treat PAW as an orchestration layer above these four products.

PAW must work correctly even if these four projects do not exist.

They may only be considered historical inspiration for ideas such as:

```text
QwenPaw
→ inspiration: skill-based personal agent concepts

DeepSeek Harness
→ inspiration: replaceable execution architecture

NotebookLM
→ inspiration: source-grounded knowledge and citations

Antigravity
→ inspiration: capable coding/execution agents
```

PAW must implement its own abstractions for these concepts.

Build a personal AI agent that runs primarily from the terminal:

```text

```

There should be one coherent user-facing agent identity.

Workers, models and executors are implementation details.

# 2. CORE PHILOSOPHY

PAW follows these principles.

## 2.1 CLI first

The primary interface is:

```bash
paw
```

GUI is optional and outside the initial scope.

---

## 2.2 Local first

Prefer local storage and local computation whenever practical.

Cloud services may be used when they provide clear value.

---

## 2.3 Zero-daemon by default

Running:

```bash
paw ...
```

must not require permanent background infrastructure.

Default:

```text
start
→ perform task
→ persist state
→ exit
```

No Redis, server or daemon should be required for normal operation.

---

## 2.4 Cheap before expensive

Simple jobs should use:

```text
deterministic tools
↓
small/local model
↓
larger model
```

Only escalate when justified.

---

## 2.5 One agent identity

Do not expose a swarm of personalities to the user.

Conceptually:

```text
USER
 │
 ▼
PAW
 │
 ├── worker
 ├── worker
 ├── model
 └── executor
```

The workers do not own user identity.

---

## 2.6 Skills before improvisation

PAW should first determine whether it already knows a reliable procedure for the requested task.

```text
request
 ↓
skill discovery
 ↓
relevant skill
 ↓
task planning
```

Do not make the LLM invent workflows repeatedly when a tested skill exists.

---

## 2.7 Task Graph before Agent Swarm

Complex work should become a graph of tasks.

Example:

```text
Implement feature
      │
      ├── research
      ├── inspect repository
      ├── design
      ├── implement
      ├── test
      └── verify
```

Do not create multiple autonomous agents unless parallelism provides measurable benefit.

---

## 2.8 Context is selected, not dumped

Never automatically send:

```text
entire conversation
+
entire memory
+
entire repository
+
all skills
+
all research
```

to a model.

Context selection is a first-class subsystem.

---

## 2.9 Memory and history are different

Memory:

```text
what should PAW remember?
```

Task Ledger:

```text
what happened?
```

Never treat complete execution logs as personal memory.

---

## 2.10 Replaceable infrastructure

Models, model providers and coding executors must be replaceable.

PAW owns the abstractions.

Providers implement them.



# 18. CAPABILITY ROUTER

Capability Router decides:

```text
WHAT SHOULD EXECUTE THE TASK?
```

Not:

```text
WHICH MODEL SHOULD BE USED?
```

These are separate decisions.

Executors implement a common contract.

Conceptually:

```python
class Executor(Protocol):

    async def execute(
        self,
        task: Task,
        context: TaskContext,
    ) -> TaskResult:
        ...
```

Initial executors:

```text
MockExecutor
LocalExecutor
```

Only after the architecture is proven should a coding executor be added.
