# Runtime end-to-end harness

Proves PAW can carry one **real** engineering task end to end on a repository it
was not written against. This is not a fixture tier and not an accuracy
benchmark: it is a demonstration that the loop is wired, gated, durable and
verifiable.

## What it does

On `textdistance` at a pinned revision, it runs the task found in that
repository:

> The six token-based classes in `algorithms/token_based.py` each repeat
> `self._get_counters(*sequences)` followed by `self._intersect_counters(...)`.
> Extract that pair into one helper `_prepare_token_counters` on `Base`.

Stages, each through PAW-owned components:

| Stage | Component |
|---|---|
| ingest the foreign repo | `KnowledgeSourceManager`, `KnowledgeChunkStore` |
| compile context for the task | `ContextCompiler.compile_manifest` |
| generate the helper | local model via Ollama |
| gate the writes | `PolicyGuard` → ASK |
| prove nothing was written early | file hash before/after the gate |
| perform the writes | `LocalFilesystemExecutor` |
| verify | the target repo's own test suite |
| audit | `TaskLedger` |

## Running it

Needs a network fetch and a local Ollama server, so it is **manual and opt-in**;
pytest does not collect it.

```bash
bash benchmarks/runtime/fetch_corpus.sh            # clones + pins d6a68d6
ollama serve &                                     # local model
uv run python benchmarks/runtime/run_e2e.py
```

## Why the oracle is differential

The target repository already has **28 failing tests at the pinned revision**
(edit-distance alignment, pre-existing). So "all green" is the wrong bar. The
harness runs the suite twice — pristine and modified — and requires the failing
set to be **identical**.

The suite is run with a fixed `--hypothesis-seed` **and an isolated
`HYPOTHESIS_STORAGE_DIRECTORY`**. Without the isolation the failing set moved
between runs, because hypothesis replays from a shared example database; that
made a no-regression claim unsupportable until it was fixed.

## What the oracle actually caught

While this harness was being written, the oracle **rejected a broken refactor
three times**: 72 failed, then 61, then 72, before the rewiring was correct at
28. All three were faults in the transformation, not in PAW. Without a real
oracle the same change would have been reported as a success while breaking 44
lines.

That is the point of this harness: **PAW can refuse a wrong change**, not merely
run one.

## Provenance of the change under test

- The **helper** is generated by the local model (`qwen2.5-coder:7b`).
- The **six call-site rewrites** are a deterministic mechanical transformation.
  Each class consumes the counters differently, and the local model is not yet
  reliable enough to be trusted with them.

Both writes go through Policy → approval → executor, so the gate evidence is
complete.

## Limits — read before quoting this as proof

- It proves the **pipeline**, on one task, in one repository.
- It does not measure local model quality, and the local model still produces
  incorrect code on some prompts.
- It reuses the foreign corpus' own test suite as the oracle; that is strong
  evidence for this repository and says nothing about arbitrary projects.
- The corpus is cloned at a pinned revision, never vendored: PAW does not take
  ownership of third-party code.
